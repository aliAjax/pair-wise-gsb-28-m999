# 配送任务拖拽排班（双人调度 · 乐观锁）

- 行业：物流
- 技术栈：React、Vite、TypeScript、Ant Design、dnd-kit、zustand
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 解决的问题

两个调度员在两台电脑上同时排单，晚保存的一方会把先排结果盖回去。
本系统用**修订序号（乐观锁）**解决，并对**在途单**使用独立的移交确认流程。

## 规则

1. 每张配送单带修订序号（#N），任何保存都会推进。
2. 拖到司机名下或在列内调整顺序时，按拖拽瞬间的本地快照序号提交：
   - 与服务端一致 → 生效，序号 +1；
   - 已被另一台电脑推进 → **本次拖放整笔转入冲突区，不覆盖任何占用**，
     冲突记录列出：单号、原司机（本地快照占用）、本地序号、服务端当前序号、当前占用、操作目标、原因、时间。
3. 已发车（在途）的单子**锁定不可拖动**：
   - 只能由当前占用的**原司机**登记移交（承接司机 + 移交原因）；
   - **承接司机登录确认后才换占用**并推进序号，也可拒绝；拒绝则占用不变。
4. 未派单、在途单、冲突记录、移交记录全部持久化，重新打开仍在。
5. 页面分层：
   - **排班拖拽**：未派区 + 三个司机列，dnd-kit 拖拽；
   - **配送资料**：配送单台账、新增、改资料、删除；
   - **冲突区**：冲突记录处理（按当前序号重放到目标列尾 / 忽略留痕）+ 在途移交登记处理。
   - 冲突判断逻辑在 `src/conflict.ts`，与存储、UI 完全解耦（纯函数）。

## 如何复现“两台电脑冲突”

数据保存在浏览器 localStorage，**另开一个浏览器标签页即为第二台电脑**：

1. 标签页 A、B 都打开本应用；
2. 在 A 把某张单拖给刘师傅；
3. 切到 B（B 工作区仍显示旧快照），把同一张单拖给孙师傅；
4. B 顶部出现他端改动提示，提交时序号核对失败，操作进入“冲突区”，
   A 的排班结果保留；
5. 在冲突区点“按当前序号重试”，单子会以最新序号落到目标列尾。

单标签页可点排班页右上角 **“模拟他端抢先保存”** 一键制造序号差。

## 目录

```
src/
  types.ts                     领域模型（配送单 / 冲突 / 移交）
  conflict.ts                  冲突判断层：序号核对、禁拖校验、列内重排（纯函数）
  storage.ts                   服务端真相持久化 + storage 事件跨标签页同步
  data.ts                      司机、身份、种子数据
  store.ts                     状态层：乐观锁提交、移交流程、冲突留痕
  components/
    OrderCard.tsx              配送单卡片（在途锁定）
    HandoverModal.tsx          在途移交登记弹窗
  pages/
    ScheduleBoard.tsx          拖拽排班页
    OrderDataPage.tsx          配送资料页
    ConflictCenter.tsx         冲突区页
```
