# 配送任务拖拽排班

- 行业：物流
- 技术栈：React、Vite、TypeScript、Ant Design、dnd-kit、zustand
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 业务规则

两名调度员在不同电脑（演示中可用两个浏览器标签页）同时排班，晚保存的一方不再覆盖先排结果：

1. **修订序号（revision）**：每张配送单携带修订序号，拖到司机名下或在队列/未派池内调整顺序，成功落子后序号 +1。
2. **落子核对**：拖动开始时卡片捕获携带序号，落子时与服务端（localStorage 充当）当前序号核对。
   - 序号一致：排班生效并保存。
   - 序号不一致：本次操作整体进**冲突区**，列出单号、原司机、携带序号、当前序号和被拦下的操作，先排结果不受影响；本端底稿同步刷新为最新版本。
3. **已发车锁定**：已发车的单子不能拖动。需要换车时只能由**原司机**登记承接司机和移交原因，**承接司机确认后**才换占用（序号 +1）；也可拒绝，占用保持不变。
4. **持久化**：未派、已排、已发车、冲突记录、移交记录全部落 localStorage，重新打开页面都保留。
5. **三页分离**：
   - 「配送资料」：新增配送单、查看资料与修订序号；
   - 「拖拽排班」：dnd-kit 拖拽排班、发车、在途移交登记；
   - 「冲突记录」：冲突判断结果与在途移交确认，互不耦合。

## 复现并发冲突

- 单页演示：卡片上点「模拟他端+1」（另一台电脑晚保存、服务端序号 +1），再拖动该卡片，即进冲突区。
- 真实双端：开两个标签页，A 页先排一单，B 页卡片仍停留在旧序号，B 再拖即冲突；点「重新载入最新数据」可拉取最新底稿。

## 目录

- `src/domain/`：类型与冲突判断引擎（纯函数，可单测）
- `src/data/`：localStorage 持久化与种子数据
- `src/state/`：zustand 状态层（乐观锁保存、跨端记录合并）
- `src/pages/`：配送资料、拖拽排班、冲突记录三个页面
- `src/components/`：投放区、配送单卡片
